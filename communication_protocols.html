📊 五大通信协议概览

这五种通信协议在嵌入式系统中广泛应用，各有优缺点。以下是它们的核心特性对比：

协议 传输方式 工作模式 线路数 波特率 距离 应用场景
UART 异步串行 全双工 2-3条 300-921600 bps <15米 调试、MCU通信、传感器
RS232 异步串行 全双工 3-9条 300-115200 bps <50米 工业设备、计算机外设
RS485 异步串行 半双工 2-4条 300-115200 bps <1200米 工业控制、远距离通信
SPI 同步串行 全双工 4-5条 100kHz-10MHz+ <1米 芯片间通信、SD卡、Flash
IIC/I2C 同步串行 全双工 2条 100kHz-400kHz <10米 传感器集成、主板、外设

⚡ UART (通用异步收发器)

基本概念

UART是一种异步串行通信协议，广泛用于MCU与PC、MCU与传感器之间的通信。是RS232的物理层底层协议。

数据格式 1个起始位 + 8数据位 + 1奇偶位 + 1-2停止位 = 10-11比特
传输速率 常用：9600, 115200 bps
工作模式 全双工(TXD/RXD)
电压标准 逻辑电平(3.3V/5V)
引脚定义
TXD (发送) ←─ 发送数据
RXD (接收) ─→ 接收数据
GND (地线) ←→ 公共参考

交叉连接方式：
MCU1 TXD → MCU2 RXD
MCU1 RXD ← MCU2 TXD
MCU1 GND ─ MCU2 GND (必须连接)
时序特性
UART数据帧结构
起始位 8个数据位 奇偶位 停止位 ↓ ↓↓↓↓↓↓↓↓ ↓ ↓↓ 0 1 0 1 0 1 0 1 0 P 1 1 ↑ ↑ 低电平 可能有奇偶检验 例如发送字符'A' (0x41): 起始位: 0 数据位: 1 0 0 0 0 1 0 (0x41 = 01000001, LSB先发) 停止位: 1 总耗时: (1+8+1+1) / 波特率
硬件简单、成本低廉；易于调试；无需时钟同步
抗干扰能力弱；距离短；无握手信号

📡 RS232 (推荐标准232)

基本概念

RS232是建立在UART基础上的通信标准，规定了逻辑电平与物理电平之间的转换。使用专用芯片(如MAX232)进行电平转换。

电平标准 逻辑1: -3V ~ -15V
逻辑0: +3V ~ +15V
相对UART反向
接头类型 DB9(9针)或DB25(25针)
通常使用DB9
传输距离 可达50米
比UART更强
握手信号 支持RTS/CTS
流量控制
DB9引脚定义
DB9针脚：
1 - CD (载波检测)
2 - RXD (接收数据) ← 重要
3 - TXD (发送数据) ← 重要
4 - DTR (数据终端就绪)
5 - GND (地线) ← 必连
6 - DSR (数据集就绪)
7 - RTS (请求发送)
8 - CTS (清除发送)
9 - RI (振铃指示)

最小连接方案： 2(RXD) - 3(TXD) - 5(GND)
接头标准统一；距离远；可靠性高；工业应用广泛
需要电平转换芯片；体积大；成本比UART高

🏭 RS485 (推荐标准485)

基本概念

RS485是一种多点通信标准，支持多个设备在同一总线上通信。采用差分信号传输，抗干扰能力强，传输距离远。

传输方式 差分信号
A线vs B线
拓扑结构 多点总线
最多256个设备
工作模式 半双工
轮流收发
特点 距离远、抗干扰
高EMI环境理想
硬件拓扑
RS485总线结构：

┌─ 设备1 ─┬─ 设备2 ─┬─ 设备3 ─┬─ 设备4 ─┐
│ │ │ │ │ │ │ │ │
A ─┼───┼─────┼───┼─────┼───┼─────┼───┼─ 终端电阻120Ω
│ │ │ │ │ │ │ │
B ─┼───┼─────┼───┼─────┼───┼─────┼───┼─ 终端电阻120Ω
│ │ │ │ │ │ │ │
GND─┼───┼─────┼───┼─────┼───┼─────┼───┼─
│ │ │ │ │ │ │ │
└─ 收发 ─┴─ 收发 ─┴─ 收发 ─┴─ 收发 ─┘

三线制连接：
A+ (非反相) ─────────────┐
B- (反相) ─────────────┤ 所有设备并联
GND (地线) ─────────────┘

四线制连接： (带流控)
A+ / B- / GND / 控制线
差分信号说明

逻辑1： A > B (A为高电平, B为低电平)

逻辑0： A < B (A为低电平, B为高电平)

差分传输方式使得即使有噪声干扰，两线之间的差值仍然清晰，从而实现长距离可靠传输。

多点通信、传输距离远(1200m)、抗干扰强、成本低
半双工(不能同时收发)、需要地址管理、收发转换复杂
应用示例
  • 工业控制系统(Modbus协议)
  • 智能家居网络
  • 传感器网络
  • PLC与传感器通信
  • 远距离数据采集

⚙️ SPI (串行外设接口)

基本概念

SPI是一种同步串行通信协议，由Motorola开发。具有速度快、全双工、硬件简单的特点。常用于MCU与Flash、SD卡、无线模块等外设通信。

时钟驱动 主设备提供时钟信号
从设备跟随时钟
工作模式 全双工
MOSI + MISO
速率范围 100kHz - 10MHz+
取决于硬件
点对点 一个主，多个从
通过CS选择
引脚定义 (4线)
标准4条信号线：

SCK (Serial Clock) → 时钟信号，由主设备产生
MOSI (Master Out Slave In) → 主发从收数据线
MISO (Master In Slave Out) → 主收从发数据线
CS (Chip Select) → 芯片选择信号(低有效)

多从设备连接：

┌─ 从设备1 CS
主设备 ─┼─ 从设备2 CS
├─ 从设备3 CS
└─ 从设备4 CS

(SCK、MOSI、MISO共享)
工作原理

1. 移位操作

主从设备都有8位移位寄存器。SCK每来一个上升(或下降)沿，数据移位一位。

2. 全双工特性

发送1个字节的同时，可以接收1个字节。耗时：8个时钟周期。

3. 片选信号

CS拉低 → 通信开始 → 数据传输 → CS拉高 → 通信结束

SPI模式 (CPOL/CPHA)
模式 CPOL CPHA 说明
Mode 0 0 0 SCK空闲时为低；数据在上升沿采样
Mode 1 0 1 SCK空闲时为低；数据在下降沿采样
Mode 2 1 0 SCK空闲时为高；数据在下降沿采样
Mode 3 1 1 SCK空闲时为高；数据在上升沿采样
速度快、全双工、硬件简单、易于实现多从设备
需要4条线(不含CS可3条)、距离短、无流控、从设备无法主动通信
应用场景
  • Flash存储器读写
  • SD卡通信
  • 无线模块(WiFi、蓝牙)
  • LCD屏幕驱动
  • 传感器接口

🔗 IIC/I2C (集成电路总线)

基本概念

I2C (Inter-Integrated Circuit) 是Philips开发的同步串行通信协议。采用开漏输出和上拉电阻，支持多主多从。广泛应用于传感器、EEPROM等芯片集成。

两线总线 SDA + SCL
简洁高效
总线类型 开漏/开栅
需要上拉电阻
多主多从 支持多个主设备
总线仲裁
速率分级 标准:100kHz
快速:400kHz
硬件连接
I2C总线拓扑：

+5V (或3.3V)
↑
Rp (上拉电阻, 通常4.7K)
↑
┌───┐
SDA┤ ├─────┬─────┬─────┐
│ │ │ │ │
SCL┤ ├─────┼─────┼─────┤
│ │ │ │ │
└───┘ 从1 从2 从3
主 芯片 芯片 芯片

最小连接：
SCL ← 时钟线，所有设备共享
SDA ← 数据线，所有设备共享
GND ← 公共地
工作原理

1. 开漏驱动

每个设备只能将线拉低，不能主动拉高。高电平通过上拉电阻实现。

2. 起始和停止条件

START： SCL高时，SDA由高变低
STOP： SCL高时，SDA由低变高

3. 数据传输

SCL低 → 改变SDA (发送数据)
SCL高 → 从设备采样SDA

4. 应答信号

接收方拉低SDA 1个时钟周期 → ACK (应答)
接收方保持SDA高 → NACK (非应答)

I2C帧结构

典型I2C通信序列

[START] [地址7位] [读写1位] [ACK] [数据8位] [ACK] ... [STOP]

例: 读取地址0x68的芯片数据

1. START → SCL高时, SDA从高变低
2. 发送地址 0110100 (7位地址)
3. 发送读写位 0 (写操作)
4. 接收ACK
5. 发送寄存器地址(数据)
6. 接收ACK
7. ... (可以读写多个字节)
8. STOP → SCL高时, SDA从低变高
地址格式
地址类型 长度 说明
7位地址 7位 标准I2C，支持127个设备
10位地址 10位 扩展地址，支持1023个设备，使用较少
只需2条线、集成度高、支持多主多从、硬件简单、成本低
速率较低(100-400kHz)、距离短(10m左右)、总线仲裁复杂
常见I2C器件
  • EEPROM (AT24C256等)
  • 实时钟芯片 (DS1307、PCF8563等)
  • 温湿度传感器 (DHT等)
  • 加速度计/陀螺仪 (MPU6050等)
  • OLED显示屏
  • 触摸屏控制器

🔍 协议对比深度分析

异步协议 (UART/RS232/RS485)：

  • 无时钟信号，接收方与发送方时钟独立
  • 需要约定好波特率
  • 需要起始位和停止位进行同步
  • 容易受时钟偏差影响(通常不超过5%)

同步协议 (SPI/I2C)：

  • 有时钟信号，发送方和接收方时钟同步
  • 接收方严格按照时钟采样
  • 可以更高的速率传输
  • 需要额外的时钟线

全双工 (UART/RS232/SPI/I2C)：

  • 可以同时发送和接收数据
  • 需要独立的发送和接收线路
  • 通信效率高
  • 硬件更复杂

半双工 (RS485)：

  • 同一时刻只能发送或接收
  • 需要转换控制信号(RE/DE)
  • 线路简洁(通常只需两条线)
  • 成本更低
  • 需要合理的通信规程避免冲突

点对点 (UART/RS232/SPI的多个CS)：

  • 一对一或一对多独立连接
  • 每条链路独立
  • 简单可靠
  • 线路数较多(多个从设备需多个CS)

多点总线 (RS485/I2C)：

  • 多个设备共享总线
  • 寻址灵活
  • 线路数少
  • 需要协调机制(总线仲裁)
  • 扩展性好

典型嵌入式系统架构：

主控MCU (如STM32)
│
├─ UART ─────→ USB转串口 ─→ 电脑调试
│
├─ I2C ──────→ 温度传感器、EEPROM、RTC
│
├─ SPI ──────→ Flash存储器、SD卡、无线模块
│
└─ RS485 ────→ 远端传感器网络 (多个节点)

该配置可以实现：
- UART用于开发调试
- I2C集成主板外设(低速，距离近)
- SPI访问大容量存储(高速)
- RS485通信远端设备(远距离，多节点)
💡 学习建议
  • 初学者： 先掌握UART/RS232，理解串行通信基础
  • 进阶： 学习I2C和SPI，分别代表多点总线和高速通信
  • 工业应用： 深入RS485和Modbus协议
  • 实践： 用示波器观察时序波形，加深理解
  • 工具： 使用逻辑分析仪(Logic Analyzer)调试通信
